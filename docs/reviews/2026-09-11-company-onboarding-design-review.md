# 新增公司方案复核与剩余设计

日期：2026-09-11
状态：设计审查完成；以下修订建议待用户审阅，尚未开发。

## 结论与已确认方向

采用发行人专属适配，接受等待，以数据质量优先。页面负责申请、进度、问题与质量报告；通过强制校验和适配复核后发布。保持本地单用户运行，估值假设独立确认。总体方向可行，但前述方案尚存在身份、发布一致性、复核执行与行业适用性缺口。

本次检查了 domain/companies.py、spec/schema.sql、refresh/service.py、ingestion/sec/sync.py、config/mappings/segment_axes.yaml 和既有返工记录。工作树在审查前干净；本次只新增审查文档，没有运行或修改产品代码。以下是设计结论，不代表新能力已实现。

## 必须修正的设计

1. **发行人与证券分开。** CIK 是发行人身份；增加 security（独立 security_id、issuer_id、股类、交易所、币种）和带生效期间的 ticker 别名。相同 CIK 复用财报与适配任务，不合并不同股类的行情。路由解析有歧义时返回候选证券。市值与每股估值必须校验不同股类和 ADR 换算口径，不得直接把某股类价格乘公司总股数。
2. **专属适配明确执行者。** 本地任务执行器负责采集、候选映射和确定性校验；首次适配需要维护者审阅官方证据、修正配置并运行回归。页面提供问题详情、证据预览和审查包导出；首期配置维护通过本地版本化文件和校验/导入命令完成。未知解析方式需要维护者开发解析器。点击新增不会自动唤起 Codex，也不能承诺无人介入必然完成。复核记录必须绑定准确的配置哈希、数据版本与检查结果，变更后失效。
3. **发布数据与配置一起版本化。** 增加 dataset_version 与 publication，后者固定适配、解析器、规则、源快照及数据版本。候选财务、分部和派生指标隔离构建；所有正式查询绑定同一个 publication_id。文件先按内容哈希持久化，数据库事务最后切换发布指针。失败遗留文件可回收，不能破坏旧发布。只版本化 issuer_profile 不够。
4. **按披露制度确定覆盖门槛。** 普通季度申报公司目标为三年及八季度；历史不足时检查全部可用申报与实际缺口。20-F/6-K 公司不强制不存在的季度链；未实现对应披露模板时显示待适配，不能伪装通过或把半年数拆成季度数。季度和年度比较必须按同一会计口径及重述版本对齐。
5. **财务校验分清恒等式与诊断。** 资产负债勾稽按报表的可赎回权益等项目完整定义；现金桥包含汇率及受限现金口径。EPS 不是一律用净利润除稀释股数，优先股、两类法和反稀释规则需要适配。分部勾稽包含抵销和未分配项目。容差来自披露精度与版本化规则，不能靠放宽阈值消除未知差异。
6. **缺失状态分开。** 使用 VERIFIED、NOT_DISCLOSED、NOT_APPLICABLE、MISSING、CONFLICT、UNSUPPORTED。只有经过证据核实且行业模板允许的前两类非数值状态可免除特定检查；核心缺失、冲突和未支持仍阻塞。无法取得某项原始 context 时不得伪造，应补抓原始申报或明确证据等级并按门槛阻塞。
7. **行业模板限制计算能力。** 银行、保险、REIT、IFRS 和 ADR 不能继承普通工业公司净债务及 FCFF 模型。可以提交申请，但模板尚未实现时保持待适配；财报发布不意味着估值可用。不承诺首期实现所有行业模板。
8. **迁移已有公司不等于已通过新标准。** AAPL/MSFT 保留现有数据及使用路径，标记旧版待复核；重放验证后才授予新质量认证。迁移前备份并演练恢复，不把种子数据直接标为通过。

## 剩余设计：任务与异常恢复

- 采用一个本地应用进程拥有 DuckDB 写入权，持久化任务记录与单写入执行器；复用并统一现有刷新写入调度。首期不引入独立多进程写库队列。
- 状态区分排队、采集、生成候选、待人工适配、校验、待复核、已发布、失败、已取消。显示已完成步骤数量及耗时，不展示无法估算的精确百分比或完成时间。
- 步骤绑定输入哈希与尝试编号；启动时恢复中断记录，核对快照后重试。网络退避重试有上限；解析或口径冲突转为待适配，不能无限重试。服务关闭期间任务不会继续运行。
- 取消在安全步骤边界生效；可以重试或重新入队。刷新失败保留旧发布，明确显示其数据截止日期及待解决问题。
- 识别结果包含身份快照指纹，创建任务时再次核对；同一发行人不重复采集，同一证券不重复添加。ticker 输入不接受任意 URL、路径或代码。
- 发布条件为强制检查通过、所有阻塞项解决且首次适配复核签署有效；执行器随后自动完成原子发布。没有忽略错误的强制发布入口。
- 已审核适配下的常规数据更新可在同一规则集校验通过后发布；新 concept、分部结构或重述等口径变化触发新复核。

## 剩余设计：估值与页面一致性

- 复用现有 valuation_assumption_set / valuation_plan 等结构，先做字段差距分析，再决定是否增加独立 profile 表，避免双重事实来源。
- 初始估值使用同一发布版本的财务、明确日期的行情和可追溯股类换算。用户确认增长、资本成本、再投资和终值等实际模型所需输入；系统建议与用户判断分开记录。
- 用户确认不能绕过模型不适用、币种错配或关键数据缺失。财务或适配版本更新后，原估值保留并标记待复核，不自动改写旧结果。
- 公司页展示覆盖范围、缺失与不适用项目、来源、发布版本及复核时间。行情过期时仍可阅读已验证财报，但当前价格估值受阻并说明原因。
- 管理层、风险等可选模块按实际就绪状态显示；不得生成没有证据的结论。需要哪些模块参与核心发布由版本化行业模板明确规定。

## 剩余设计：验收与执行顺序

1. 身份及发布版本基础：迁移演练、恢复验证、多股类/历史 ticker、现有公司回归。
2. 持久化任务与候选隔离：中断恢复、重复提交、取消重试、候选数据不泄漏、发布失败保留旧版。
3. 专属适配与复核闭环：配置校验/导入、证据预览、审查包、签署失效机制及核心规则反例。
4. 先完整接入一家新增普通经营公司：以官方申报人工核对的预期数值作为验收基准，再用不同财年或复杂分部公司验证可扩展性。最终选择的公司与快照在实施计划中固定。
5. 页面新增、进度、质量报告和估值门禁：浏览器端验证刷新持久化、错误状态、证券切换及旧响应隔离。
6. AAPL/MSFT 新标准复核和完整回归；逐项更新专用进度文档，分别记录实现、验证、复核和阻塞，不能以勾选代替证据。

自动测试使用固定官方快照，预期值从原始报表独立核对，不由待测解析器生成。覆盖累计转单季、53 周财年、重述、拆股、分部抵销、缺披露、来源丢失、错误行情股类、无适用模板及事务中断。另做一次受控在线端到端验证，确认实际来源访问与字段变化；测试通过不等于所有美股已适配。

## 自审结果

已补齐执行者、发布对象、证券身份、迁移认证、复核有效期及模型适用性。剩余需要用户审阅的核心产品取舍是首期采用“系统采集校验 + 维护者专属适配复核”；等待时长受复核与适配工作影响。后续实施计划需将上述顺序拆为可独立验收的小阶段。
