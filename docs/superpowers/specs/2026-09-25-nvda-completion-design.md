# NVDA 行情、治理与估值闭环设计

**日期：** 2026-09-25
**状态：** 已确认，待实施计划
**依赖：** 公司建档闭环已发布；公司刷新进度体验见 PR #1

## 1. 背景与目标

NVDA 已完成公司身份、证券身份、财务事实、分部数据和正式发布，但用户仍不能把它当作一家公司正常研究：行情没有入库，管理层与内部人交易为空，估值显示“待配置”却没有审核入口。

本阶段的目标是关闭这三个产品缺口，使 NVDA 在不绕过质量门禁的前提下达到以下状态：

1. 刷新可以取得并保存 NVDA 行情，页面展示真实观测时间和提供方。
2. 刷新可以读取 SEC 实际披露文件，生成董事、高管和 Form 4 非衍生交易记录。
3. 用户可以在估值页审核系统生成的默认方案，调整五个核心假设，并显式确认后启用估值。
4. 所有失败都显示具体阶段、原因和可执行的下一步，不把“等待审核”伪装成后台仍在运行。

## 2. 已核实的根因

### 2.1 行情

`config/market/sources.yaml` 只登记了 AAPL 和 MSFT，NVDA 缺少 Nasdaq/Tencent 的符号映射。两个现有行情适配器均能直接返回 NVDA 报价，因此不需要增加新供应商。

### 2.2 管理层与 Form 4

代理声明抓取和解析可正常得到 NVDA 的高管与董事。Form 4 同步却把文件名硬编码为 `form4.xml`；SEC submissions 返回的真实主文档是动态名称，例如 `wk-form4_1789766132.xml`。带 `xslF345X06/` 的链接是浏览器渲染 HTML，不是应当保存和解析的原始 XML。

### 2.3 估值

估值默认配置只有 AAPL 和 MSFT，没有 NVDA 的版本化参数。后端已经支持按证券、正式发布、模型版本和完整假设绑定确认记录，但前端只显示门禁提示，没有取得草稿和提交确认的产品入口。

## 3. 方案比较与决策

### 方案 A：后台自动补齐并自动确认

优点是最快开放估值。缺点是把研究假设冒充用户确认，破坏现有质量原则；后续财务版本变化时也无法证明用户审核过哪一组输入。因此不采用。

### 方案 B：管理员在数据库或命令行确认

复用现有后端接口，开发量较小。缺点是普通用户仍会停在“待配置”，也正是当前体验失败的原因。因此不采用。

### 方案 C：系统生成草稿，用户在估值页审核并确认（采用）

系统从正式发布的财务事实和版本化发行人配置生成完整草稿；页面解释每项来源，开放五个核心研究假设供调整。用户点击“确认并启用估值”后，后端保存与当前证券和发布版本绑定的确认记录，页面随即进入现有估值工作区。

该方案保留明确的用户确认，又不要求用户从空白表单手工录入全部 DCF 数据。

## 4. 系统设计

### 4.1 行情配置

- 在现有市场配置中加入 NVDA 的 Nasdaq 主源和 Tencent 备用源符号。
- 继续使用现有提供方优先级、货币校验、新鲜度判断和安全降级逻辑。
- 不把抓取时间当作行情时间；页面继续展示供应商给出的 `observed_at`。
- 如果主源失败而备用源成功，任务结果必须显示实际使用的提供方；两者均失败时保留旧快照并明确失败原因。

### 4.2 SEC 管理层同步

- Form 4 下载地址统一使用 submissions 返回的 `primaryDocument`，与代理声明的处理方式一致。
- 对 Form 4 主文档路径做规范化：移除仅用于展示的 XSL 路径前缀，下载归档目录中的原始 XML。
- 原始快照文件沿用现有不可变存储规范，文件名来自主文档而不是固定为 `form4.xml`。
- 回放模式从快照元数据读取实际文件名，保证离线重跑和线上抓取走相同解析路径。
- 单个 Form 4 损坏不应抹掉已成功解析的代理声明或其他 Form 4；结果中分别报告成功数量、跳过数量和错误摘要。

### 4.3 NVDA 估值默认配置

- 为 NVDA 添加独立、版本化的 beta、税前债务成本、五年收入增长路径及 Bear/Base/Bull 场景。
- 配置值属于“研究假设”，不得标注成 SEC 事实或自动推导结论。
- 财务基准、利润率、税率、资本开支、折旧摊销、净现金与稀释股数仍由当前正式发布的标准化事实生成；缺少关键事实时禁止确认。
- 模型仍使用现有 FCFF DCF 版本，不在本阶段增加新估值模型。

### 4.4 估值审核接口

增加一个只读草稿接口，返回：

- 当前 `security_id`、`publication_id` 和模型版本；
- 完整的 DCF 输入；
- 每项输入的来源、日期、规则、回退原因及历史参照；
- 当前是否已有匹配的确认记录；
- 无法生成草稿时的结构化阻塞原因。

确认继续使用现有 `PUT /companies/{ticker}/valuation-profile`，但前端必须提交草稿返回的完整身份和假设。后端在写入前重新校验证券归属、正式发布、模型版本、币种、ADR/股数口径及 DCF 约束，避免用户确认过期草稿。

### 4.5 估值审核界面

当门禁为 `NEEDS_CONFIGURATION` 时，估值区不再只显示说明文字，而显示一个可操作的审核卡：

1. 顶部说明“这是研究假设审核，不是价格预测承诺”。
2. 展示证券、财务发布版本、模型版本和关键事实日期。
3. 展示完整输入来源；仅允许编辑五个核心假设：五年收入增长路径、第五年营业利润率、WACC、永续增长率、稳定期 ROIC。
4. 实时显示 Bear/Base/Bull 预览和主要模型风险，但预览不落库。
5. 用户勾选“我已审核该证券和本发布版本的假设”后，才能点击“确认并启用估值”。
6. 确认成功后重新获取公司目录和估值数据，不要求用户手动刷新页面。

如果门禁为 `BLOCKED`，不显示确认按钮，只展示缺失数据、受影响模块和修复动作。

## 5. 数据流

### 5.1 刷新

用户发起刷新 → 后台分别同步财务、分部、治理和行情 → 每个阶段独立记录结果 → 成功数据写入正式数据库 → 前端轮询得到终态 → 自动重新加载公司目录、页面模块与数据新鲜度。

Form 4 的核心链路为：submissions `primaryDocument` → SEC 原始 XML → 不可变快照 → `parse_form4` → 内部人交易表。

### 5.2 估值确认

估值门禁 → 获取当前发布的默认草稿 → 用户审核/调整五项假设 → 本地预览 → 提交完整确认载荷 → 后端重新校验并保存 `CONFIRMED` assumption set → 目录能力变为 `READY` → 自动加载现有估值工作区。

新的正式发布会产生新的 `publication_id`，旧确认不会自动迁移。页面应保留旧方案作为历史记录，但要求用户审核基于新事实重建的草稿。

## 6. 错误与状态表达

- `QUOTE_CONFIG_MISSING`：缺少证券行情映射；提示维护配置，不显示“刷新成功”。
- `SEC_PRIMARY_DOCUMENT_MISSING`：submissions 没有主文档；保留 filing 身份并提示重新抓取或人工检查。
- `SEC_FORM4_PARSE_FAILED`：文件已取得但不是有效 ownership XML；显示 accession 和文档名。
- `VALUATION_DEFAULT_UNAVAILABLE`：关键财务事实或发行人研究配置不足；列出缺失项。
- `VALUATION_DRAFT_STALE`：用户提交时发布版本、模型版本或完整假设已变化；不落库，要求重新加载审核卡。
- 网络或单个外部源失败不得清空上一次成功数据；页面必须区分“旧数据仍可读”和“本次刷新失败”。

## 7. 测试与验收

### 7.1 自动化测试

- 行情配置单元测试：NVDA 主备符号、币种和提供方顺序正确。
- SEC 单元测试：动态 Form 4 文件名、XSL 展示路径、原始 XML、回放模式、单文件失败继续执行。
- 估值单元测试：NVDA 默认参数可生成且所有元数据有来源；无关键事实时拒绝生成。
- API 集成测试：草稿身份完整、确认成功、过期发布拒绝、币种/ADR/多证券股数门禁保持有效。
- 前端测试：待配置卡可审核并确认、阻断态不可确认、成功后自动进入估值页、接口失败可重试且不丢用户编辑。
- 回归测试：AAPL/MSFT 行情、管理层和估值行为不变。

### 7.2 正式数据验收

在正式数据库副本上完成后再作用于正式库：

1. NVDA 刷新后有一条可追溯的最新行情快照，页面显示供应商观测时间。
2. 最新代理声明生成非空高管和董事记录。
3. 至少一个有效 Form 4 生成非衍生交易；如最近 filing 合法但没有非衍生交易，页面显示真实原因而不是笼统失败。
4. 未确认前估值保持 `NEEDS_CONFIGURATION`。
5. 用户审核确认后能力变为 `READY`，无需浏览器手动刷新即可展示估值。
6. 再次刷新财务并产生新发布后，旧确认不会静默复用，页面重新要求审核。

## 8. 范围边界

本阶段不增加新的行情供应商，不构建通用管理员后台，不自动替用户确认研究假设，不改变现有 DCF 数学模型，也不处理下一优先级的 AAPL/MSFT 历史数据复审。行情刷新和公司页面刷新体验的进一步优化仍保留为后续事项；本阶段只保证 NVDA 闭环所需的正确刷新和自动重载。
